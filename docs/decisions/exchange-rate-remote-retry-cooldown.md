# 환율 캐시가 만료돼도 원격 조회는 5분에 한 번만 다시 시도한다

- 정한 날: 2026-11-24
- 근거: 즐겨찾기 카드를 공유 `ExchangeViewModel`이 만들도록 바꾸는 Android PR의 codex 리뷰, 이 결정의 Android·iOS PR
- 적용: Android `ExchangeRateRepositoryImpl`, iOS `ExchangeRateRepositoryImpl` (두 플랫폼 같은 값)

## 규칙

- 저장소는 마지막으로 원격 조회를 시작한 시각을 메모리에 기억한다. 성공·실패를 가리지 않는다.
- 캐시가 있고 12시간 TTL이 지났어도, 마지막 원격 조회에서 5분이 지나지 않았으면 원격을 부르지 않고 캐시를 돌려준다.
- 캐시가 비어 있으면 쿨다운을 두지 않는다. 지금처럼 원격을 시도하고, 실패하면 오류를 던진다.
- 사용자가 누른 새로고침(`refreshExchangeRates`)은 쿨다운과 관계없이 늘 원격을 부르고, 시도 시각을 갱신한다.
- 시도 시각은 저장하지 않는다. 앱을 다시 켜면 처음부터 센다. 기기 시각이 마지막 시도보다 이전으로 돌아가면 쿨다운으로 보지 않는다.

## 이유

- 로컬 `fetchedAt`은 앱이 받은 시각이 아니라 서버 문서의 `rateFetchedAt`이다. Cloud Functions가 매일 11:10 KST(실패하면 12:30)에
  쓰므로, 매일 23:10부터 다음 동기화까지 약 12시간은 원격 조회가 성공해도 같은 문서를 받아 캐시가 계속 만료 상태다.
  서버 동기화가 실패한 날은 `rateFetchedAt`이 바뀌지 않아 더 길어진다.
- 실패나 만료를 기억하지 않으면 환율을 묻는 호출마다(즐겨찾기 카드 수만큼, 통화를 바꿀 때마다) Firestore를 다시 읽는다.
  오프라인이면 매번 실패를 기다린다.
- 캐시가 없으면 돌려줄 것이 없다. 환율 화면의 "다시 시도"는 `getSupportedCurrencies`를 부르므로 여기서 막으면 재시도가 먹통이 된다.
- 서버 문서는 하루 한두 번만 바뀌므로 5분이면 새 환율을 늦게 보는 일은 거의 없고, 연결이 돌아온 뒤에도 금방 다시 받는다.

## 하지 않은 것

- TTL 기준을 앱이 받은 시각으로 바꾸지 않았다. 그러면 TTL의 뜻(문서가 12시간 넘게 지나면 새 문서를 찾는다)이 바뀌고 캐시 스키마도 손대야 한다.
- 시도 시각을 DataStore·UserDefaults에 저장하지 않았다. 앱을 켤 때 한 번 더 읽는 정도는 받아들인다.
